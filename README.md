# 차곡여행 · Travel Agent

**항공권 → 호텔 → 일정 → 일정에 따른 식당 검색** 순서로 여행을 계획하는 한국어 웹 에이전트입니다. 일정은 여행 중에도 수정할 수 있고, 식당 검색에는 항상 현재 일정의 시간·위치와 전후 동선을 전달합니다.

## 시작하기

Python 3.12 이상과 [uv](https://docs.astral.sh/uv/)가 필요합니다.

```bash
cd /workspace/Travel-Agent
export UV_CACHE_DIR=/workspace/travel-agent-tools/cache
uv sync --frozen --extra dev
.venv/bin/python -m travel_agent.server --port 8000
```

기본 실행은 이 컴퓨터에서만 접근할 수 있는 포트 8000에 바인딩합니다. 클라우드 환경에서는 내부 HTTP 요청으로 검증할 수 있습니다. 공개 배포용 인증·TLS·다중 사용자 권한 관리는 포함하지 않습니다.

### AI 검색 설정

환경 설정에서 `TRAVEL_AGENT_API_KEY`를 보안 입력하고 실행 환경에 반영한 뒤 서버를 재시작하세요. `.env.example`은 변수 이름을 보여주는 예시이며 `.env`를 자동으로 읽지 않습니다. 실제 키를 소스나 채팅에 넣지 마세요.

| 변수 | 용도 | 기본값 |
| --- | --- | --- |
| `TRAVEL_AGENT_API_KEY` | OpenAI API 인증 | 없음 |
| `TRAVEL_AGENT_MODEL` | 웹 검색을 지원하는 Responses API 모델 | `gpt-4.1-mini` |
| `TRAVEL_AGENT_DB` | SQLite 여행 데이터 경로 | 현재 디렉터리의 `.data/trips.sqlite3` |

SDK에 키를 명시적으로 전달하며, HTTPS `api.openai.com`으로 요청합니다. 플랫폼의 예약 변수인 `OPENAI_API_KEY`를 새로 설정할 필요가 없습니다. 모델·웹 검색 사용 권한과 API 비용이 발생할 수 있습니다.

API 키 없이도 여행 생성, 항공·호텔 확정, 일정 추가·수정·삭제와 저장을 사용할 수 있습니다. 키가 없으면 AI 검색 버튼을 비활성화하고 가짜 추천을 만들지 않습니다.

## 사용 흐름

1. **항공권**: 에이전트에 출발지·목적지·여행 날짜·인원·수하물·예산을 알려 후보를 검색합니다. 선택한 항공편의 현지 도착·귀국편 현지 출발 날짜와 시간을 직접 확정합니다.
2. **호텔**: 확정된 항공 기간에 맞는 호텔을 비교한 뒤 이름·지역·체크인·체크아웃을 확정합니다.
3. **일정**: 에이전트에 관심사와 여행 속도를 알려 동선 초안을 받습니다. 추천 내용을 일정표에 직접 추가하고, 이동·관광·식사·휴식 시간을 편집합니다.
4. **식당**: 일정표의 ‘이 일정 근처 식당’을 선택하고 취향·예산·알레르기 등을 입력합니다. 선택한 일정과 전체 여행 상태를 기준으로 검색합니다. 고른 식당은 일정의 장소·메모에 직접 반영합니다.

AI 추천은 확정 정보를 자동 변경하지 않습니다. 일정표를 저장하면 서버에 즉시 반영되고 새로고침 뒤에도 유지됩니다. 입력 중인 미저장 내용은 자동 저장하지 않습니다.

### 일정 갱신 규칙

- 항공 정보가 바뀌면 호텔과 일정이 초기화됩니다. 호텔 정보가 바뀌면 일정이 초기화됩니다. 화면에서 먼저 확인을 받습니다.
- 동일한 항공·호텔 정보를 다시 저장하면 기존 계획을 유지합니다.
- 일정의 개별 수정·삭제는 확정한 항공·호텔에 영향을 주지 않습니다.
- 체류 시간 밖의 일정, 겹치는 일정과 중복 ID를 거부합니다. 일정은 목적지 현지 날짜·시간을 사용합니다.
- 검색 중 여행 상태가 바뀌면 오래된 추천을 폐기합니다. 일정·단계·식당 기준 일정이 바뀌면 이전 추천도 숨깁니다.
- 버전 비교로 여러 창의 동시 수정이 서로 덮어쓰지 않게 합니다. 충돌 시 새로고침 후 다시 수정하세요.

## 검증

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
node --check travel_agent/static/app.js  # Node.js가 있는 경우
```

테스트는 단계 순서, 체류 시간·일정 충돌, 확정 정보 변경 시 초기화, SQLite 재연결, 동시 수정 거부, 실제 HTTP API와 UI 파일 제공, 최신 일정 기반 SDK 요청을 확인합니다. AI 테스트는 모의 HTTP 응답을 사용하므로 실제 모델·웹 검색 접근을 증명하지 않습니다.

## 구성

```text
travel_agent/
  domain.py       # 여행 상태와 단계별 검증
  store.py        # SQLite 저장·버전 충돌 감지
  agent.py        # 단계별 AI 지침·웹 검색·출처 추출
  server.py       # HTTP API와 정적 UI 제공
  static/         # 한국어 반응형 웹 화면
tests/            # 도메인·HTTP·저장·SDK 회귀 테스트
```

주요 API:

- `POST /api/trips`: 새 여행 생성
- `GET /api/trips/{id}`: 여행 불러오기
- `POST /api/trips/{id}/flight`, `/hotel`: `{ "version": 0, "data": { ... } }`
- `POST /api/trips/{id}/activities`: `{ "version": 2, "data": [ ... ] }`
- `POST /api/trips/{id}/advice`: `{ "version": 3, "stage": "restaurants", "activity_id": "...", "message": "..." }`
- `GET /api/health`: 서버 상태·키 존재 여부 확인. 키 값은 반환하지 않습니다.

## 첫 버전의 범위

- 웹 검색 기반 후보 조사입니다. 항공·호텔 공급사의 실시간 예약 재고 API, 결제·예약 기능은 연결하지 않았습니다. 검색으로 확인되지 않은 가격을 확정가로 간주하면 안 됩니다.
- AI 검색 응답은 출처 링크와 조회 시각을 표시합니다. 웹 검색에서 얻은 가격·영업시간은 예약 사이트나 공식 사이트에서 최종 확인해야 합니다.
- 한 여행에 하나의 목적지와 하나의 숙소를 확정하는 흐름입니다. 당일치기, 여러 도시·숙소, 항공 시간대 자동 변환·공항 이동 시간 계산은 후속 확장 대상입니다.
- 브라우저는 마지막 여행 ID를 로컬 저장소에 기억합니다. 새 여행 생성 시 기존 데이터는 서버에 남지만 여행 목록·계정 동기화는 아직 없습니다. 여행 ID가 있으면 API로 다시 불러올 수 있습니다.
- AI에 요청하면 입력한 여행 상태·메모가 모델 제공자에게 전달됩니다. 여권번호·결제정보는 입력할 필요가 없습니다.

현재 클라우드 인스턴스에서는 실제 API 키가 없어 실모델 호출은 검증하지 않았습니다.
